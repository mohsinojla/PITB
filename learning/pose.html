▶cv2.cvtColor(src, code)

Converts an image between color spaces (e.g. BGR ↔ RGB, BGR ↔ grayscale, BGR ↔ HSV).

Why it's needed here

OpenCV always loads/stores images as BGR channel order, but mediapipe's models were trained expecting RGB. Skipping this swap doesn't crash anything — it just silently feeds the model color-swapped pixels, so skin tones and clothing colors come out wrong and detection gets noticeably less accurate.

Used in this project
result = pose.process(cv2.cvtColor(person_bgr, cv2.COLOR_BGR2RGB))
When to reach for it
  • Any time you hand an OpenCV image to a library that expects RGB (mediapipe, PIL, most deep-learning models).
  • cv2.COLOR_BGR2GRAY before edge detection / thresholding, since those usually work on single-channel images.
  • cv2.COLOR_BGR2HSV when you want to filter by color/hue (HSV separates color from brightness, which BGR doesn't).
Rule of thumb: OpenCV in, OpenCV out — convert only at the boundary where another library or a human viewer expects a different order.
▶mp.solutions.pose.Pose(static_image_mode, model_complexity)

Constructs mediapipe's pose-landmark detector. It finds 33 body keypoints (nose, shoulders, elbows, wrists, hips, knees, ankles, etc.) in an image.

Key parameters
  • static_image_mode=True — treat every call as an unrelated photo (no tracking between video frames). Slower but more accurate per single image; use False for video/webcam streams so it can track and interpolate between frames.
  • model_complexity — 0 (fastest/least accurate) to 2 (slowest/most accurate). We use 2 since this runs once per photo, not in real time.
Used in this project
with mp_pose.Pose(static_image_mode=True, model_complexity=2) as pose:
    result = pose.process(rgb_image)
When to reach for it
  • Any task needing body position: fitness apps, gesture control, AR clothing/filters, sizing a garment to a torso (as we do here).
It's used as a context manager (with ... as pose:) so the underlying native model resources are released automatically when the block exits.
▶pose.process(image)

Runs the actual neural-network inference on one RGB image and returns a result object.

What you get back

result.pose_landmarks.landmark — a list of 33 landmarks, each with .x, .y (normalized 0–1, relative to image width/height), .z (relative depth) and .visibility. If no person is found, result.pose_landmarks is None.

Used in this project
if not result.pose_landmarks:
    raise RuntimeError("No person/pose detected in the person image.")
lm = result.pose_landmarks.landmark
Always check for None before indexing landmarks — a blurry photo, a cropped body, or a non-person image will return no landmarks.
▶mp_pose.PoseLandmark (landmark index → pixel coords)

An enum giving human-readable names (LEFT_SHOULDER, RIGHT_HIP, …) for the 33 landmark indices, instead of memorizing numbers.

Normalized → pixel conversion

Landmarks come back as fractions of image size (0.0–1.0), so you must multiply by the image's actual width/height to get pixel coordinates.

Used in this project
def pt(landmark):
    p = lm[landmark]
    return np.array([p.x * w, p.y * h])

left_shoulder = pt(mp_pose.PoseLandmark.LEFT_SHOULDER)
When to reach for it
  • Whenever you need a specific joint by name (shoulders/hips for clothing fit, wrists for gesture position, ankles for a jump-height app, etc.).
▶mp.solutions.selfie_segmentation.SelfieSegmentation(model_selection)

A separate, lighter mediapipe model that outputs a per-pixel probability of "this pixel belongs to a person" — a soft silhouette mask, not landmarks.

Key parameter
  • model_selection — 0 = general model, 1 = "landscape" model (faster, tuned for wider shots). We use 1.
Used in this project
with mp_selfie.SelfieSegmentation(model_selection=1) as seg:
    result = seg.process(rgb_image)
mask = result.segmentation_mask  # float32, 0..1 per pixel
When to reach for it
  • Background removal/blur (video-call style backgrounds), compositing a person onto a new scene, or — as here — restricting where a warped garment is allowed to be drawn so it doesn't spill onto the background.
This mask is soft (values between 0 and 1, not just 0/1), which is exactly what you want for smooth edges when blending — thresholding it too hard gives jagged silhouettes.
