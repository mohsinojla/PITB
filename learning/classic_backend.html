▶cv2.findHomography(srcPoints, dstPoints)

Given two sets of 4+ matching points, computes the 3×3 homography matrix — the perspective transform that maps one flat plane onto another (handles rotation, scale, skew, and perspective foreshortening, not just simple resizing).

Used in this project
homography, _ = cv2.findHomography(src_quad, target_quad)
# src_quad    = the garment's 4 corners (top-left/right, bottom-left/right)
# target_quad = the corresponding 4 points on the person's torso
When to reach for it
  • Mapping a flat image onto another flat surface at an angle: document scanning ("de-skew this photo of a page"), placing a logo on a tilted surface, AR overlays, panorama stitching, and here — fitting a garment photo onto a torso.
Needs at least 4 point correspondences (a quad → quad mapping). For a simpler case — e.g. just rotate/scale/translate, no perspective skew — cv2.getAffineTransform (3 points) is lighter-weight.
▶cv2.warpPerspective(src, M, dsize)

Applies a homography matrix (from findHomography, or built manually) to actually resample an image — i.e. it draws the pixels of src onto the output canvas, distorted according to M.

Used in this project
warped = cv2.warpPerspective(garment_bgra, homography, (w, h))
# output canvas is the same size (w, h) as the person photo,
# so the warped garment lands directly in the right place
When to reach for it
  • Always paired with findHomography (or a manually-built matrix) — one computes the transform, the other applies it to pixels.
Because garment_bgra has an alpha channel, the warp also carries the transparency along for free — pixels outside the original garment silhouette warp to alpha 0.
▶cv2.GaussianBlur(src, ksize, sigmaX)

Smooths an image (or in our case, a mask) by averaging each pixel with its neighbors, weighted by a bell-curve (Gaussian) falloff.

Used in this project
combined_mask = cv2.GaussianBlur(combined_mask, (0, 0), sigmaX=self.feather_px / 3)
Why blur a mask?

A hard-edged mask (0s and 1s only) produces a visible, jagged cut-out line where the garment meets the photo. Blurring turns the mask edge into a soft gradient (0 → 1 over a few pixels), which — when used as a blend weight — produces a smooth, feathered transition instead of a sticker-cutout look.

When to reach for it
  • Noise reduction before edge detection, feathering compositing masks (as here), softening an image for a stylized/dreamy look.
  • ksize=(0,0) tells OpenCV to auto-compute the kernel size from sigmaX — convenient when you only care about "how strong," not the exact kernel dimensions.
▶np.clip(array, a_min, a_max)

Clamps every value in an array to a range — anything below a_min becomes a_min, anything above a_max becomes a_max.

Used in this project
combined_mask = np.clip(combined_mask, 0.0, 1.0)
Why

Blurring can push mask values slightly outside the valid 0..1 range due to floating-point rounding at the edges; clipping guarantees the mask stays a valid blend weight before it's used in later math or converted to an 8-bit image.

When to reach for it
  • Any time you do math on pixel values (blurring, blending, brightness/contrast adjustments) and need to guarantee the result is still a valid image range before saving or converting dtype.
▶Case study — why this pipeline doesn't use cv2.seamlessClone anymore

Poisson/gradient-domain blending (cv2.seamlessClone) is the standard textbook answer for hiding a composite seam: instead of a plain alpha "cut and paste," it blends the source region's gradients into the destination so lighting/color continuity across the edge looks natural. It was this project's original blending method:

result = cv2.seamlessClone(warped_rgb, person_bgr, mask_u8, center, cv2.NORMAL_CLONE)
What actually happened

On a real photo, results consistently came out looking like a faint, "translucent" ghost of the garment — the original shirt still clearly visible underneath — even though the garment was fully opaque and correctly positioned. It looked exactly like a transparency/alpha bug, and wasn't one.

Ruling out the obvious suspects first
  • Checked the mask wasn't the problem: same washed-out result with the softly feathered mask and with a cleanly thresholded binary mask (no gradient values at all).
  • Checked the clone mode wasn't the problem: cv2.NORMAL_CLONE and cv2.MIXED_CLONE both produced it (MIXED_CLONE was actually worse — it discarded almost the entire garment).
  • Saved the garment image right before the clone call and confirmed it was still fully vivid, high-contrast, and correctly colored going in.

That isolated it to seamlessClone itself: its Poisson solve re-integrates the source patch using the destination's values at the mask boundary. When that boundary sits over something very different-looking from the new garment — here, literally the old shirt being replaced — satisfying those boundary conditions pulls the whole patch's contrast/saturation down toward the old, duller garment, badly enough to look like a see-through ghost rather than a subtle color grade.

The fix

Dropped seamlessClone entirely in favor of a plain feathered alpha blend (below) — the same Gaussian-blurred combined_mask already computed for edge softness, used directly as a per-pixel blend weight. It kept the garment's real colors intact and looked visibly more realistic on every test photo.

The general lesson
  • The "textbook better" algorithm for a task (Poisson blending is unambiguously more sophisticated than alpha blending) isn't automatically the better choice for a specific input — verify on the actual data, don't assume sophistication implies quality here.
  • A result that looks like a specific, familiar bug (transparency) can have a completely different root cause (contrast collapse) that only shows up once you check the very next value in the pipeline, not just "did this step run".
▶Alpha blending: src*mask + dst*(1-mask)

The classic "over" compositing formula, computed directly with NumPy array arithmetic — this is the pipeline's actual blend step (see the case study above for why, not cv2.seamlessClone).

Used in this project
mask3 = (combined_mask * self.opacity)[:, :, None]   # add a channel dim so it broadcasts over B,G,R
result = (warped_rgb.astype(np.float32) * mask3 +
          person_bgr.astype(np.float32) * (1 - mask3)).astype(np.uint8)
for every pixel p: result[p] = mask[p] * warped[p] + (1 - mask[p]) * original[p] \_______________/ \____________________/ fully "warped" where fully "original" where mask == 1 mask == 0 (smooth mix in between, thanks to the Gaussian blur)

opacity is folded directly into the same mask multiply here, rather than a separate fade-after-blend step — simpler than it needed to be back when seamlessClone (a hard-region operation, not a graded blend) was still in the loop; see advanced_features.html for that history.

When to reach for it
  • Any straightforward compositing task — simple, fast, predictable, and (per the case study above) not automatically worse-looking than gradient-domain blending.
Cast to float32 before the multiply — multiplying uint8 arrays directly wraps around (overflows) instead of clamping, corrupting the result.
