▶ImageOps.exif_transpose() — load photos the way they actually look tryon/io_utils.py

A phone almost never rotates the actual pixels when you take a sideways/upside-down shot — it just writes an EXIF Orientation tag and lets the viewer app rotate on display. cv2.imread ignores that tag completely, so a "portrait" phone photo can load as landscape-and-rotated with no error at all — it just quietly breaks pose detection (mediapipe expects an upright person) and garment quad detection alike.

Used in this project
def imread_oriented(path):
    with Image.open(path) as img:
        img = ImageOps.exif_transpose(img)   # actually rotates the pixels per the EXIF tag
        if img.mode not in ("RGB", "RGBA"):
            img = img.convert("RGBA" if "A" in img.mode else "RGB")
        arr = np.array(img)
    return cv2.cvtColor(arr, cv2.COLOR_RGB2BGR)   # Pillow is RGB, OpenCV wants BGR

main.py now calls this instead of cv2.imread directly, for both the person photo and every garment photo — it mirrors cv2.imread's "return None on failure" contract (wrapped in a try/except) so the rest of the CLI's error handling didn't need to change.

Verified, not assumed

Tested by rotating a sample photo's pixels 90° and hand-writing an EXIF orientation tag onto the copy, then confirming imread_oriented on that file reproduced the original (unrotated) pixels — a round-trip check, not just "it ran without an exception."

Gotchas
  • cv2.imread returns None on failure instead of raising — always check for None, don't assume a successful read. This still applies here.
  • Pillow images are RGB channel order; OpenCV arrays are BGR — always cv2.cvtColor(..., cv2.COLOR_RGB2BGR) (or RGBA2BGRA) when handing a Pillow-loaded array to OpenCV, or colors come out swapped (red ↔ blue).
  • Takes a plain string path — on Windows, wrap pathlib.Path objects in str(...) first.
▶cv2.imwrite(path, img)

Saves a NumPy image array to disk. The output format (JPEG, PNG, …) is inferred entirely from the file extension in path.

Used in this project
cv2.imwrite(str(output_path), result)
When to reach for it
  • Any time a processed image needs to be persisted rather than just displayed.
Use .png for anything with transparency or that must stay lossless (masks, intermediate debug images); .jpg is fine for the final photo-style result and is much smaller.
▶argparse.ArgumentParser

Standard-library tool for turning command-line arguments (--person photo.jpg --output out.jpg) into a Python object with named attributes, plus free --help text and error messages for missing/invalid args.

Used in this project
parser = argparse.ArgumentParser(description="Try clothes on a person photo before buying.")
parser.add_argument("--person", required=True, help="Path to the photo of the person.")
parser.add_argument("--backend", choices=["classic", "diffusion"], default="classic")
parser.add_argument("--flip-garment", action="store_true", help="...")
parser.add_argument("--opacity", type=float, default=1.0, help="...")
args = parser.parse_args()
# args.person, args.cloth, args.output, args.backend, args.flip_garment, args.opacity
When to reach for it
  • Any script meant to be run from a terminal with configurable inputs, rather than hard-coded file paths.
  • choices=[...] gives you free validation — an invalid --backend value fails immediately with a clear error, no manual if checks needed.
  • action="store_true" — a flag needing no value, e.g. --flip-garment; becomes False unless passed, then True. Note the dash in the flag name becomes an underscore on the parsed object: args.flip_garment.
  • type=float — argparse only ever hands you raw strings from sys.argv unless told otherwise; type=float converts "0.5" → 0.5 (and rejects non-numeric input with a clear error) rather than the script doing float(args.opacity) itself everywhere it's used.
Range validation argparse can't do alone

choices=[...] only works for a fixed, enumerable set of values — it can't express "any float between 0 and 1." For --opacity, that's checked manually right after parse_args():

if not 0.0 <= args.opacity <= 1.0:
    print("Error: --opacity must be between 0 and 1.", file=sys.stderr)
    sys.exit(1)
Chained comparisons (0.0 <= x <= 1.0) read naturally in Python and evaluate exactly like the math notation they mirror — no need for 0.0 <= x and x <= 1.0.
▶pathlib.Path

Object-oriented file path handling — cross-platform (handles / vs \ automatically), with methods instead of stringly-typed os.path calls.

Used in this project
person_path = Path(args.person)
if not person_path.exists():
    ...
output_path = Path(args.output)
output_path.parent.mkdir(parents=True, exist_ok=True)   # create output/ if missing
print(output_path.resolve())                             # full absolute path, for a clean confirmation message
Handy methods used here
  • .exists() — check a file/folder is actually there before trying to use it.
  • .parent — the containing directory, so you can ensure it exists before writing into it.
  • .mkdir(parents=True, exist_ok=True) — create nested directories, and don't error if they already exist.
  • .resolve() — turn a relative path into an absolute one, useful for user-facing "saved to ..." messages.
